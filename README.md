# Здрасте KPI — безопасная базовая версия

Небольшой Python-сервис формирует KPI-отчёт по данным iiko, Google Sheets и PostgreSQL и отдаёт его по HTTP.

## Что исправлено

- учётные данные и идентификаторы внешних источников удалены из кода;
- TLS-проверка включена по умолчанию;
- токены и query-параметры не печатаются в журналах;
- добавлены опциональная HTTP Basic Auth и защитные HTTP-заголовки;
- исправлена гонка фонового обновления и добавлен многопоточный HTTP-сервер;
- при частичной загрузке обязательных источников корректная история не затирается нулями;
- добавлена инициализация таблицы PostgreSQL и атомарная локальная копия;
- исправлен выбор ближайшей ступени KPI;
- расчёт дат переведён в `Europe/Moscow`;
- имя сотрудника экранируется перед вставкой в HTML;
- имя вкладки графика строится для текущего года;
- добавлены `/healthz`, ежедневное обновление в 23:00 и обновление stale-while-revalidate;
- зависимости ограничены совместимыми диапазонами.
- филиал выбирается строго по адресу `Волоколамское шоссе 95/2с8`, а все
  OLAP-запросы фильтруются по подтверждённому UUID `Department.Id`;
- формула «Допов» закреплена тестами: `Допы Бар + Допы Кухня +
  Бутилированные напитки + Алкоголь`.

## Первый запуск

1. Используйте `.env.example` как перечень настроек и задайте их в Render
   либо в окружении локального процесса. Сам файл `.env` намеренно не читается
   приложением без специального загрузчика.
2. Обязательно задайте `IIKO_SERVER`, `IIKO_LOGIN` и `IIKO_PASSWORD`.
   `IIKO_ORG_NAME` уже настроен на `Волоколамское шоссе 95/2с8`.
   `IIKO_ORG_ID` можно добавить как вторую строгую проверку того же филиала.
3. Задайте `DATABASE_URL` либо полный набор `PG_*`.
4. При необходимости задайте идентификаторы Google Sheets.
5. Для Excel/fallback-режима задайте `BARISTA_NAMES` и `WAITER_NAMES`,
   разделяя ФИО точкой с запятой.
6. Установите зависимости и запустите:

```powershell
python -m pip install -r requirements.txt
python server.py
```

Проверка: `http://localhost:8765/healthz`.

На Render запуск дополнительно требует iiko-настройки, постоянное хранилище
PostgreSQL и хотя бы одну из переменных `BARISTA_NAMES` / `WAITER_NAMES`.
Неполностью настроенный deploy завершится до открытия порта, чтобы платформа
не заменила рабочую версию страницей без данных.

## Доступ

Чтобы временно закрыть отчёт паролем, задайте обе переменные:

```text
REPORT_USERNAME=...
REPORT_PASSWORD=...
```

По решению владельца страница остаётся общедоступной, поэтому обе переменные
пусты. Для корпоративной эксплуатации предпочтительнее SSO/reverse proxy на
уровне платформы.

## Филиал и OLAP

Приложение находит ровно один активный `DEPARTMENT` с именем
`Волоколамское шоссе 95/2с8`, получает его UUID и добавляет фильтр
`Department.Id / IncludeValues` в продажи, смены и категории. Перед запросами
live-каталог `/api/v2/reports/olap/columns` должен подтвердить, что поле имеет
ID-тип и разрешает фильтрацию. При отсутствии или неоднозначности приложение
не делает нефильтрованный запрос и показывает последнюю корректную копию.
Месячная история хранится под ключом, изолированным по филиалу: записи прежней
версии без фильтра не участвуют в KPI этого адреса.

## Оставшийся вопрос владельца

- Следует ли заменить сопоставление людей по фамилии на стабильные employee ID?

Категория iiko называется `Бутилированные напитки`. В текущем бизнес-правиле
она трактуется как указанная владельцем бутилированная вода. Если внутри неё
есть лимонады или соки, категорию в iiko следует разделить.
